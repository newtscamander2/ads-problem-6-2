\begin{exercise}[D'ary heap]
	A d-ary heap is like a binary heap, but (with one possible exception)
	nonleaf nodes have d children instead of two children. In all parts of
	this problem, assume that the time to maintain the mapping between
	objects and heap elements is O(1) per operation.

	a. Describe how to represent a d-ary heap in an array.

	b. Using $\theta$-notation, express the height of a d-ary heap of n elements in
	terms of n and d.

	c. Give an efficient implementation of EXTRACT-MAX in a d-ary
	max-heap. Analyze its running time in terms of d and n.

	d. Give an efficient implementation of INCREASE-KEY in a d-ary
	max-heap. Analyze its running time in terms of d and n.

	e. Give an efficient implementation of INSERT in a d-ary max-heap.
	Analyze its running time in terms of d and n.

\end{exercise}


\section*{Comment}

\section*{Our solution}


\section*{a}
A d'ary heap can both be represented in the form of a tree structure and in the form of an array. When making an array of numbers in a d'ary heap data structure it is important to denote the index of each node. For a d'ary heap we have that a node has (up to) $d$ children, except at the end of the heap.

To find the index of a node as the k'th child of a parent node, where k is 0-indexed, we can use the following formula:
$$i_{child} = i_{parent} \cdot d + k_{child}$$

If A in a d'ary heap we furhtermore have that $A[i_{parent}] > A[i_{child}]$ for a max-heap and $A[i_{parent}] < A[i_{child}]$ for a min-heap.

You can then find all the children of a node as
$$\sum_{k=0}^{d-1}i\cdot d + k$$

An example could be $d=5$. Then the children would be
$$i \cdot5, i \cdot 5 + 1, i \cdot 5 + 2, i \cdot 5 + 3, i \cdot 5 + 4$$


\section*{b)}
To count a d-ary trees height you find the amount of nodes to the lowest leaf. The trees are created from left to right, and is therefore always complete (there are no holes in a tree / no incomplete branches).
The count of elements in a d-ary heap can be found using $n=1 + d + d^2 + d^3 + d^4 + \cdots + d^h=\sum_{i=0}^{h}d^i = \frac{d^{h+1}-1}{d-1}$.

Since we want to find the height $h$ we have to solve for $h$.
We can find $n$ amount of elements in a filled heap with the equation $n = \frac{d^{h+1}-1}{d-1}$. $n$ is therefore.

$$n \leq \frac{d^{h+1}-1}{d-1}$$
We can then find a lowerbound for when a heap has a step with only $1$ element.
$$n \geq \frac{d^{h}-1}{d-1} + 1$$

We can now write the inequality
$$\frac{d^{h}-1}{d-1} + 1 \leq n \leq \frac{d^{h+1}-1}{d-1}$$
$$\Downarrow$$
$$\frac{d^{h}-1}{d-1} < n \leq \frac{d^{h+1}-1}{d-1}$$
$$\Updownarrow$$
$$d^{h}-1 < n(d-1) \leq d^{h+1}-1$$
$$\Updownarrow$$
$$d^{h} < n(d-1)+1 \leq d^{h+1}$$
$$\Updownarrow$$
$$log_d{(d^{h})} < log_d{(n(d-1)+1)} \leq log_d{(d^{h+1})}$$
$$\Updownarrow$$
$$h < log_d{(n(d-1)+1)} \leq h+1$$
$$\Downarrow$$
$$h < \lceil log_d{(n(d-1)+1)} \rceil = h+1$$
$$\Updownarrow$$
$$h = \lceil log_d{(n(d-1)+1)} \rceil - 1$$

%Theta notaion!!!!????
Because $n$ is the dominant term in $\lceil log_d{(n(d-1)+1)} \rceil - 1$ because $d$ and $1$ is a constant factor we can find a $c$ such that
$$log_d{(n_0)}\cdot c \geq \lceil log_d{(n_0(d-1)+1)} \rceil - 1$$

It is therefore true that 
$$O(log_d{(n)}) = \lceil log_d{(n(d-1)+1)} \rceil - 1$$

As with Big-O notation $n$ is a dominant factor. We can therefore find a $c$ such that it is true that
$$log_d{(n_0)}\cdot c \leq \lceil log_d{(n_0(d-1)+1)} \rceil - 1$$

It is therefore true that
$$\Omega(log_d{(n)}) = \lceil log_d{(n(d-1)+1)} \rceil - 1$$

From \textbf{Theorem 3.1} we know that if $f(n) = \Omega{(g(n))}$ and $f(n) = O{(g(n))}$ then $f(n) = \Theta{(g(n))}$
$$\Theta(log_d{(n)}) = \lceil log_d{(n(d-1)+1)} \rceil - 1$$

\section*{c)}
The Extract-Max function on a max d-ary heap extracts the largets value in the heap. I a max d-ary heap that value sits at the root (or the first element stored in the array).
We can therefore remove the first element in the array, and then move the last element in the array which is smaller than the root.
To make it a Max-heap we run Max-Heapify on the heap to move the moved element down the heap to it's correct position.

\begin{center}
	\begin{minipage}{12cm}
		\begin{algorithmic}
			\Procedure{Max-Heap-Maximum}{$A$}
			\If{$\text{A.heap-size} < 1$}
			\State{$\text{\textbf{error} "heap underflow"}$}

			\EndIf

			\State{\Return{$A[1]$}}
			\EndProcedure

			\\
			\\
			\Procedure{Max-Heapify}{$A, i$}

			\State{$largest = i$}

			\For{$x = 0 \rightarrow d-1$}
			\State{$index = i+i\cdot d + x$}
			\If{$index \leq \text{A.heap-size} \text{ and } A[index] > A[largest]$}
			\State{$largest = index$}
			\EndIf
			\EndFor

			\If{$largest \neq i$}
			\State{$\text{Exchange }A[i] \text{ with } A[largest]$}
			\State{$\text{Max-Heapify}(A, largest)$}
			\EndIf

			\EndProcedure

			\\
			\\
			\Procedure{Extract-Max}{$A$}
			\State{$max = \text{Max-Heap-Maximum}(A)$}
			\State{$A[1] = A[\text{A.heap-size}]$}
			\State{$\text{Max-Heapify}(A, 1)$}
			\State{\Return{$max$}}
			\EndProcedure
		\end{algorithmic}
	\end{minipage}
\end{center}

Extract-Max does a constant amount of work on-top of Max-Heapify.
We therefore have to find the running-time of Max-Heapify to find the running-time of our program.
Max-heapify contains a loop from $0 \rightarrow d-1$ so it runs for $\Theta(d)$ for the children at each level.
We know that the height of the heap is given by $\Theta{(log_d{(n)})}$
The running-time for our implementation is therefore the running time
$$\Theta(d) \cdot \Theta{(log_d{(n)})} = \Theta{(d\cdot log_d{(n)})}$$
From the supplementary notes math cheatsheet we know that $log_b{(a)} = \frac{log_c{(a)}}{log_c{(b)}}$.
We can therefore simplify our running time for Max-heapify for $a$ d-ary heap to.
$$\Theta(\frac{d\cdot log{(n)}}{log{(d)})})$$


\section*{d)}
Max-Heap-Increase-Key has the running time $\Theta(\log_d{n})$ because it first updates a node's value to a larger key and then restores the heap property. In the while loop it traverses up the heap, doing a constant amount of work. The heap has the height $h = \log_d{n}$, thus the running time becomes $\theta(\log_d{n})$.


\begin{center}
	\begin{minipage}{12cm}
		\begin{algorithmic}
			\Procedure{Max-Heap-Increase-Key}{$A, x, k$}
			\If{$k < x.key$}
			\State{$\text{\textbf{error} "new key is smaller than current key"}$}
			\EndIf{}
			\State{$x.key = k$}

			\While{$ i > 1$ and $ A[PARENT(i)].key < A[i].key$}
			\State{exchange $A[i]$ with $A[PARENT(i)]$}
			\State{$i = PARENT(i)$}
			\EndWhile{}

			\EndProcedure{}
		\end{algorithmic}
	\end{minipage}
\end{center}





\section*{e}
Max-Heap-Insert is a function that can insert an element into the heap as the last element and then restore heap property.

Running time book: "O(lg n) plus the overhead for mapping priority queue
objects to indices."

\begin{center}
	\begin{minipage}{12cm}
		\begin{algorithmic}
			\Procedure{Max-Heap-Insert}{$A, x, k$}
			\If{$A.heap-size == n$}
			\State{$\text{\textbf{error} "Heap overflow"}$}
			\EndIf{}

			\State{$A.heap-size = $ A.heap-size $ + 1$}
			\State{$k = x.key$}
			\State{$x.key = –\infty$}
			\State{$A[$A.heap-size$] = x$}
			\State{map $x$ to index heap-size in the array}
			\State{Max-Heap-Increase-Key(A, x, k)}

			\EndProcedure{}
		\end{algorithmic}
	\end{minipage}
\end{center}
